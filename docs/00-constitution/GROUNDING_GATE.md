# Grounding gate

Status: ACTIVE — NOW ENFORCED THROUGH P4-G RECONVERGENCE

## Why this gate exists

A technically excellent framework can still produce a sterile RPG.

Therefore a major system is not implementation-ready until its intended experience is explicit.

The project reached enough P4 depth that this principle must now be enforced as a hard sequencing rule rather than a reminder.

See `P4_G_RECONVERGENCE_GATE.md`.

## Rule for all future systems

Before a major system is designed or implemented, its specification must answer:

1. What player experience does this system exist to create?
2. What rhythm does it support?
3. How could a technically correct implementation damage the spirit of the game?
4. What observable playtest result proves the system is helping?

## Grounding package

- [x] Spirit of the game.
- [x] Player life-cycle: levels 1, 10, 25, 50, 75 and 100.
- [x] Session rhythm: 30 minutes, 1 hour, 3 hours and a full weekend.
- [x] World rhythm: safe -> wild -> dangerous -> remote -> civilization.
- [x] Travel doctrine.
- [x] Combat doctrine.
- [x] Progression doctrine.
- [x] Reward doctrine.
- [x] Quest doctrine.
- [x] Settlement doctrine.
- [x] Anti-pattern catalog.
- [x] First 15-hour experiential storyboard.

## Architecture is subordinate

The plant exists to support the intended lived experience.

P3/P4 mechanisms already built are retained, but their existence does not authorize additional system breadth by itself.

Combat stress fixtures are evidence about mechanism capability, not automatic game-design decisions.

The broader grounding gate remains active. Combat work does not implicitly decide travel, progression, reward, quest, settlement, world or party doctrine.

## Exit condition

The broader gate exits when intended player life is clear enough that an engineer can reject a technically sensible feature because it would make the game feel wrong.

P4-G adds concrete deliverables and physical proof requirements for reaching that state.
