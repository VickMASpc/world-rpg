# Grounding gate

Status: ACTIVE

## Why this gate exists

A technically excellent framework can still produce a sterile RPG.

Therefore a major system is not implementation-ready until its intended experience is explicit.

## Rule for all future systems

Before a major system is designed or implemented, its specification must answer:

1. What player experience does this system exist to create?
2. What rhythm does it support?
3. How could a technically correct implementation damage the spirit of the game?
4. What observable playtest result proves the system is helping?

## Grounding package

- [x] Spirit of the game.
- [ ] Player life-cycle: levels 1, 10, 25, 50, 75 and 100.
- [ ] Session rhythm: 30 minutes, 1 hour, 3 hours and a full weekend.
- [ ] World rhythm: safe -> wild -> dangerous -> remote -> civilization.
- [ ] Travel doctrine.
- [x] Combat doctrine.
- [ ] Progression doctrine.
- [ ] Reward doctrine.
- [ ] Quest doctrine.
- [ ] Settlement doctrine.
- [ ] Anti-pattern catalog.
- [ ] First 15-hour experiential storyboard.

## Architecture is subordinate

The plant exists to support the intended lived experience.

P3 kernel implementation is authorized only within the accepted combat doctrine.

The broader grounding gate remains active. P3 work does not implicitly decide travel, progression, reward, quest, settlement, or world doctrine.

## Exit condition

The broader gate exits when intended player life is clear enough that an engineer can reject a technically sensible feature because it would make the game feel wrong.
