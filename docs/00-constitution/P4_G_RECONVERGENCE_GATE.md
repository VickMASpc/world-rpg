# P4-G — lived-experience reconvergence gate

Status: ACTIVE — BLOCKS NEW P4 FEATURE EXPANSION

This gate exists because World RPG reached a point where technically valid combat/simulation work was advancing faster than the lived-experience design that is supposed to govern it.

The correction is conservative:

- preserve the useful P1-P4 machinery already built;
- stop adding new combat systems merely because they are easy to measure;
- restore the constitution/grounding documents as the authority over implementation;
- require physical and experiential evidence before further mathematical breadth.

## Why the gate was inserted

The repository already says:

> Slow should mean spacious, gradual, and lived-in — not padded.

It also says:

> We will not let architecture become the product.

However, the active P4 branch advanced from routine combat calibration into elite, healer and dungeon-party stress fixtures while the broader Grounding Gate still lacked:

- player life-cycle;
- session rhythm;
- world rhythm;
- travel doctrine;
- progression doctrine;
- reward doctrine;
- quest doctrine;
- settlement doctrine;
- anti-pattern catalog;
- first 15-hour experiential storyboard.

P3 also still has an active real-Minecraft verification matrix with manual evidence pending.

That does not invalidate current P4 code. It means the project must reconverge before adding more breadth.

## Immediate freeze

Until this gate exits, do not add new P4 feature families merely to increase checklist coverage.

Examples currently frozen:

- new boss mechanics;
- new group-role mechanics;
- dodge/parry/block implementation;
- threat implementation solely to satisfy the synthetic dungeon fixture;
- additional combat-stat families;
- more encounter archetypes;
- more simulator abstractions without an identified grounding requirement.

Bug fixes, documentation repair, test maintenance and small changes required by the grounding work remain allowed.

## Current P4 interpretation

The existing routine, attrition, accidental-pull, interrupt, elite, healer and dungeon scenarios are retained.

They are classified as:

**mechanical stress fixtures and provisional calibration evidence.**

They prove that the production kernel/resolver/simulator can express certain rhythms.

They do not by themselves define final World RPG gameplay.

No synthetic level-20 fixture may silently become class, enemy, dungeon or party doctrine.

## P4-G deliverables

### G1 — repository truth
- [ ] STATUS reflects the real active phase.
- [ ] P2/P3/P4 issues and PRs do not claim stale heads or stale future work.
- [ ] stale design documents are either repaired or explicitly marked historical/provisional.

### G2 — player life
- [x] define the player's life at levels 1, 10, 25, 50, 75 and 100;
- [x] include geography, routines, toolkit, economy, equipment history, professions, reputation, travel knowledge and reasons to return;
- [x] identify what must feel different numerically versus experientially.

### G3 — session rhythm
- [x] define healthy 30-minute, 1-hour, 3-hour and full-weekend play rhythms;
- [x] define how preparation, travel, combat, quests, recovery, professions and return share time;
- [x] identify failure modes that turn slowness into padding.

### G4 — world rhythm and travel
- [x] define safe -> wild -> dangerous -> remote -> civilization rhythm;
- [x] freeze first-pass road, shortcut, transport, mount and navigation doctrine; keep hearth details explicitly provisional;
- [x] define what makes 20-60 minute travel valid rather than empty.

### G5 — progression/reward
- [x] define what a level means beyond XP;
- [x] define gear longevity and replacement expectations;
- [x] define wealth/trainer/repair/travel pressure at representative levels;
- [x] define what old enemies/regions should feel like at +5/+10/+20/+30 levels.

### G6 — quest/settlement life
- [x] define quest duration/chain/journal philosophy in production terms;
- [x] define towns/inns/trainers/repair/storage/professions as expedition punctuation;
- [x] define when field convenience becomes too strong.

### G7 — first 15-hour experiential storyboard
- [ ] storyboard the first province as lived time rather than a content count;
- [ ] identify roads, settlements, dangers, remembered items, unfinished places and return loops;
- [ ] include at least one visible high-level threat encountered early;
- [ ] end with a mental-map test.

### G8 — physical kernel evidence
- [ ] execute and record the required P3 entity-backed Minecraft gate matrix;
- [ ] do not weaken failed expectations to make the matrix pass.

### G9 — first province topology proof
- [ ] produce a low-cost authored topology/route prototype before production terrain;
- [ ] validate representative local, settlement, regional and expedition travel times;
- [ ] validate that geography creates decisions before investing in final world art.

## Exit condition

P4-G exits only when the team can answer, from repository documents rather than memory:

- what a normal hour of World RPG feels like;
- what changes between level 1 and level 75 besides numbers;
- why the player leaves town;
- why the player comes home;
- how the same region remains relevant over time;
- how travel creates memory rather than delay;
- how gear and quests remain in the player's life long enough to matter;
- what the first fifteen hours are actually made of;
- what evidence proves the P3 kernel works inside Minecraft rather than only in tests.

After exit, P4 may resume with a narrower purpose:

**validate doctrine-derived relationships across levels and contexts, not accumulate mechanics for their own sake.**
